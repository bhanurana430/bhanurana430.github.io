Behind the work / Innovation Challenge 2026 · Educational software 8–10 October 2026 · Prototype built 8–9 October

Teach.Reflect.Grow.

Feedback matters most when you can return to the moment that prompted it.

A recording captures a lesson, but it does not explain what to do differently the next time. We built a microteaching workspace where a teacher can revisit a precise exchange, discuss it with peers, and carry that observation into a new attempt.

  1. 01

    A recording is not a reflection.

    Teachers can upload recordings and share particular teaching iterations with reviewers. Observations belong to moments in the recording, with timestamp links, threaded replies, and visibility choices for private, selected, or shared feedback.

    The backend enforces recording ownership and iteration-level reviewer access. Those distinctions matter because a private note, an observation visible to peers, and a teacher’s own reflection should not be interchangeable.

  2. 02

    Make the next attempt part of the system.

    A teaching session can contain successive iterations. Each one keeps its own recording, feedback, and private reflection. The teacher can link specific observations as evidence for what they noticed and what they intend to change.

    I built the primary application workflow with React and Vite on the frontend, and FastAPI, SQLAlchemy, and SQLite behind it. The repository includes API tests for uploads, access boundaries, threaded feedback, and iteration persistence.

  3. 03

    Use AI as input, not a verdict.

    An optional analysis path extracts audio, transcribes it through Groq Whisper, and asks a language model to provide structured observations against selected pedagogical criteria. Results are associated with the relevant iteration rather than presented as universal scores.

    This was a hackathon proof of concept. It uses selectable prototype identities rather than production authentication, and we have not established that AI feedback improves teaching outcomes. Human interpretation remains central.

My contribution

I was the primary implementer of the application during the hackathon. Teammates contributed to interface design and other supporting work.
